Know when a Portaldot network is unhealthy, why it is unhealthy, and prove it on-chain.

Portaldot Hacker House 2026 · Node Operations & Tooling

The problem

  • A dApp developer sees "my transaction never confirms". The cause sits several layers down: a node with 0 peers, an offline GRANDPA voter, or a stalled indexer.
  • Portaldot V3 has three layers to watch: Substrate (BABE + GRANDPA), the EVM, and the explorer.
  • Today, checking them takes polkadot.js, an EVM wallet, the explorer, and knowledge of consensus internals.
  • There is also no public, verifiable record of network uptime that builders and operators can point to.
potwatch

What potwatch does

  • One command checks every layer: python -m potwatch check
  • Decodes BABE slots and authors from block headers, plus GRANDPA rounds, validators and session keys
  • 23 finding types, each with a plain-language hint
  • Output as text, HTML, Prometheus metrics, and an exit code for cron or CI
  • Read-only by construction: an RPC method allowlist, and no keys
  • Cross-network check: flags keys reused between networks
  • watch mode logs state changes
  • Rules are pure functions, tested against real captured snapshots

On-chain attestations on Portaldot EVM

  • HealthAttestation.sol is an append-only log of report digests (sha256 of canonical JSON) with network, best/finalized block, timestamp and severity
  • Anyone can re-hash the published report.json and compare it with latest(network)
  • This gives a tamper-evident uptime history for networks and node operators, a building block for operator reputation and SLAs
  • No funds held; only allow-listed reporters; stale reports rejected; 14 keyless EVM tests

Deployed and attested end to end on a local chain with the V3 chain id; public testnet deployment pending testnet tokens

Why Portaldot, and what comes next

Why Portaldot

  • V3 combines Substrate consensus with an EVM. potwatch watches both, and uses the EVM to make the results verifiable.
  • Small validator sets make early warning especially valuable right now.

Roadmap

  • Hosted public status page plus periodic on-chain attestations
  • Per-operator view: authored blocks, missed slots, GRANDPA participation
  • Alerts by webhook, Discord or Telegram
  • WASM (ink!) version of the attestation contract
